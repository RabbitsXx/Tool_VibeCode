# A/B: Claude Code ที่มี กับไม่มี Tool_VibeCode

คำถาม: ชุดนี้ช่วยจริงไหม และแลกอะไรมา? คำตอบมาจากการทดลองจริง ไม่ใช่การคาดเดา: **งานเดียวกัน โมเดลเดียวกัน (Sonnet) สิทธิ์เท่ากัน** รันซ้ำสลับ "ไม่มีชุด" (ถอนชุดออกจาก `~/.claude` ชั่วคราว เหลือ Claude Code ของผู้ใช้เปล่า ๆ) กับ "มีชุด" แล้วตรวจผลจากไฟล์ เทสต์ และ git จริง

```bash
node scripts/ab.mjs --model sonnet --out <โฟลเดอร์>        # ทั้งชุด ~60 รัน ราว $7 และ 25 นาที
node scripts/ab-report.mjs <โฟลเดอร์>                      # รายงาน HTML พร้อมพรอมต์ คำตอบดิบ log ภาพหน้าจอ
node scripts/ab-index.mjs <โฟลเดอร์แม่>                    # หน้าสรุปรวมหลายรอบ
```
ตัวทดลองคืนชุดเครื่องมือให้เสมอ แม้ล้มกลางคัน (และเทียบคอนฟิกก่อน/หลังแล้วเหมือนเดิมทุกไบต์ในการทดลองจริง)

## สรุปสั้น (เหนือสิ่งอื่นใด: ชุดนี้คือชั้นความปลอดภัยและความสม่ำเสมอ ไม่ใช่ตัวเพิ่มความเก่ง)

โมเดลเปล่า ๆ เก่งอยู่แล้วในงานรีวิว/ตรวจช่องโหว่/แก้บั๊ก/ทำ UI — **ผลเท่ากันในการทดลองนี้** ชุดนี้ให้ความต่างที่วัดได้ใน 3 เรื่อง: (1) กันการทำสิ่งอันตรายตามคำสั่ง (2) โครงงานเริ่มโปรเจกต์ที่ครบกว่าและเร็วกว่า (3) ความต่อเนื่องข้าม session เมื่อใช้ `/vibe-handoff` + `/vibe-resume` และแลกด้วยความฝืดบางจุดกับภาระต้นทุน

## สิ่งที่การทดลองนี้ค้นพบและเราแก้ (รวมบั๊กที่ชุดเองเป็นต้นเหตุ)

1. **ชุดซ่อนเครื่องมือ PowerShell ของ Claude Code** (หายใน 33/33 รัน; มีใน 33/33 เมื่อไม่ติดตั้งชุด) สาเหตุ: กฎ `deny` แบบ `Bash(...)` ใด ๆ ทำให้ Claude Code ตัดเครื่องมือ PowerShell ทิ้ง ยืนยันด้วยการแยกแยะทีละกฎ แก้ด้วยกฎคู่ `PowerShell(...)` และ `vibe verify` บังคับต่อไป
2. **คีย์จริงลอดเข้า `.env.example`** (ช่องโหว่ของ guard-write) แก้แล้ว
3. **`/vibe-handoff` ฝังการตัดสินใจของผู้ใช้ไว้ใต้ "Gotchas" และ `/vibe-resume` ไม่ยกขึ้นมา** แก้ด้วยหัวข้อ "Decisions in force"
4. **`/vibe-sec` ยังพิมพ์ค่าคีย์จริง 2/6 ครั้ง** แก้ด้วยพรอมต์ที่ห้ามชัดขึ้น → 0/4
5. **ตัวติดตั้งชนข้อผิดพลาด `EPERM` บน Windows** เมื่อ `settings.json` ถูกโปรเซสอื่นเปิดค้าง (และทิ้งไฟล์ชั่วคราว) แก้ด้วยการลองใหม่ + fallback + ไม่ทิ้งไฟล์ค้าง
6. (ก่อนหน้านี้ใน E2E) `/vibe-start` ไม่บังคับ Assumptions / done-when, `/vibe-test` ไม่มีนโยบายแก้โค้ดโปรดักชัน, การเขียน `.env` ผ่าน shell

## ข้อจำกัด (อ่านก่อนเชื่อ)

- **โมเดลเดียว (Sonnet) เครื่องเดียว Windows** ตัวอย่างน้อย (2–5 รันต่อเงื่อนไข ต่อรอบ) ผลของโมเดลไม่คงที่ ผลต่างเล็ก ๆ ไม่มีนัยสำคัญทางสถิติ แพทเทิร์นที่ซ้ำทุกรอบ (S2, S3, S4, ความฝืดของ push, W1) น่าเชื่อกว่าตัวเลขเดี่ยว
- "ไม่มีชุด" ยังมีการตั้งค่าอื่นของผู้ใช้ (`@RTK.md`) และตัวป้องกันในตัวของ Claude Code
- โหมด `-p` ไม่มีคนตอบ งานระดับ "ถาม" จึงถูกปฏิเสธ ผู้ใช้โต้ตอบจะเห็นหน้าต่างถามและอนุญาตได้
- งานสั้น เล็ก ไม่ครอบคลุมโปรเจกต์ใหญ่ ฐานข้อมูล หรือการทำงานหลายชั่วโมง ไม่ได้วัดคุณภาพของโค้ดนอกเหนือจากเช็กเชิงโครงสร้าง
- รอบที่ 3 และ 4 รันเฉพาะงานที่แก้ (S2/C1/SEC1) ด้วยจำนวนรันน้อย (3–4 ต่อฝั่ง) เพื่อยืนยันการแก้ ไม่ใช่การวัดซ้ำทั้งชุด
- ตัวชี้วัด W1 ตรงกับสิ่งที่ชุดสร้าง จึงเอนเอียงเข้าข้างชุดโดยธรรมชาติ
