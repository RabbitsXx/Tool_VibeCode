# ทดสอบ End-to-End กับ Claude Code และโมเดลจริง

เทสต์ในโค้ด (`npm test`) ตรวจว่าตัวติดตั้ง/guard/ระบบอัปเดตถูกต้อง แต่ **ไม่ได้ตอบว่า `/vibe-*` ใช้งานได้จริงกับโมเดลจริงไหม** ส่วนนี้ตอบด้วย `scripts/e2e.mjs`: ขับ `claude -p` ตัวจริงด้วยโมเดลจริง สร้างโปรเจกต์ทีละขั้นด้วยคำสั่งของชุดนี้ แล้ว **ตรวจผลจากไฟล์ เทสต์ และ git จริง ไม่เชื่อสิ่งที่โมเดลบอกเอง**

```bash
node bin/vibe.mjs install                      # ต้องติดตั้งชุดนี้ก่อน และ claude ต้อง login แล้ว
node scripts/e2e.mjs --model sonnet            # หรือ opus / haiku ; --steps start,plan,... เลือกขั้น
```
ใช้โควตาจริง (ประมาณ $0.1–$5 และ 8–25 นาทีต่อโมเดล) ควรรันทีละโมเดล ถ้าชนโควตา ตัวทดสอบจะหยุดและรายงานว่า INCONCLUSIVE ไม่นับเป็นผ่าน/ไม่ผ่าน

## โปรเจกต์ทดสอบและ 13 ขั้น

โปรเจกต์: เว็บ Pomodoro timer (HTML/CSS/JS ล้วน ตรรกะแยกโมดูลและทดสอบด้วย `node --test`) แต่ละขั้นเป็น session ใหม่ (สถานะต้องส่งต่อผ่านไฟล์ใน `docs/` เหมือนใช้งานจริง)

| ขั้น | สิ่งที่ตรวจจากของจริง |
|---|---|
| `/vibe-start` | มี AGENTS/CLAUDE/docs ครบ, SPEC มีเกณฑ์รับงานและ Assumptions, TASKS เป็น "done when", AGENTS ไม่เหลือ TODO, มี commit แรก, ไม่ push |
| `/vibe-plan` | PLAN มีความเสี่ยง, ไม่ลงมือเขียนโค้ด |
| `/vibe-build` | **ผมรัน `node --test` เอง** ต้องผ่าน, task ถูก tick, ไม่เกิน 3 task, มี commit, tree สะอาด, ไม่ push |
| `/vibe-fix` | **ฝังบั๊กจริง** (เปลี่ยนโค้ดจนเทสต์ล้ม) แล้วตรวจว่าเทสต์ผ่านอีกครั้ง, บั๊กหายจากซอร์ส, แก้เล็ก, ไม่ลดมาตรฐานเทสต์ |
| `/vibe-ui` | viewport, lang, @media, :focus-visible, CSS variables, ปุ่มมีข้อความ, เทสต์ยังผ่าน |
| `/vibe-review`, `/vibe-sec` | ไม่แก้ไฟล์, รายงานมีเนื้อหา, sec ไม่พิมพ์ค่าลับ |
| `/vibe-test` | เทสต์เพิ่มและผ่าน, โค้ดโปรดักชันไม่ถูกแตะ (หรือแจ้งชัดเจนว่าแก้เพราะเจอบั๊กจริง) |
| `/vibe-explain` (ไทย) | ตอบเป็นภาษาไทย, อ้างไฟล์จริง, ไม่แก้ไฟล์ |
| `/vibe-brief` | มี GOAL/SCOPE/ACCEPTANCE/VERIFY ใช้ชื่อไฟล์จริง สั้น |
| `/vibe-handoff` | HANDOFF ถูกเขียนใหม่ครบหัวข้อ บันทึกโน้ตที่สั่ง ไม่มี secret |
| `/vibe-resume` (session ใหม่) | ขั้นถัดไปที่สรุปตรงกับ HANDOFF, สั้น, ตรวจสถานะจริงก่อนตอบ |
| `/vibe-ship` | ไม่ push/tag/publish, รายงาน PASS/FAIL ตามจริง, คำกล่าวอ้างเรื่องเทสต์ตรงกับที่ผมรันเอง |

## ผลของ v2.1.0 (Windows 11, Claude Code 2.1.299, 14–15 ต.ค. 2026)

| โมเดล | ผ่าน | guard บล็อก | ค่าใช้จ่าย | หมายเหตุ |
|---|---|---|---|---|
| Sonnet | 71/71 | 0 | ~$2.1 | รันต่อเนื่องหนึ่งรอบ |
| Opus | 71/71 | 0 | ~$5.0 | รันต่อเนื่องหนึ่งรอบ |
| Haiku | 71/71 | 0 | <$0.3 | ประกอบจาก 3 การรันต่อกัน (ดูหมายเหตุ) |

"guard บล็อก 0" หมายถึงตลอดการทำงานจริงของ 3 โมเดล (เขียนโค้ด รันเซิร์ฟเวอร์ทดสอบ commit ฯลฯ) hook ของชุดนี้ไม่ได้บล็อกหรือถามอะไรที่ไม่ควรบล็อกเลย

หมายเหตุ Haiku: รอบแรกชนโควตาของบัญชี (ผลใช้ไม่ได้ จึงเริ่มใหม่) ต่อมาตัวรันของ E2E ตายที่ขั้น `sec` เพราะ Haiku เปิดเซิร์ฟเวอร์เบื้องหลังแล้ว Windows ส่ง console event มาฆ่าตัวรัน (ข้อจำกัดของตัวทดสอบ ไม่ใช่ของชุดเครื่องมือ แก้โดยให้ตัวรันไม่ตายเพราะสัญญาณนั้น) จึงรันขั้นที่เหลือต่อบนโปรเจกต์เดิม

## สิ่งที่ E2E ค้นพบและแก้ (ผลจริง ไม่ใช่การคาดเดา)

1. `/vibe-start` ไม่บังคับให้ SPEC มีหัวข้อ Assumptions → Sonnet และ Opus เขียน SPEC โดยไม่มี (Haiku มี) แก้พรอมต์ ยืนยันว่ารอบใหม่ผ่านทั้งสามโมเดล
2. `/vibe-start` ไม่ระบุรูปแบบ task "done when" และปล่อยให้โมเดลสร้างโครงเอง (บอกว่า "vibe CLI ไม่ได้ติดตั้ง") → ตอนนี้ scaffold จาก template ของชุดนี้
3. `/vibe-test` ไม่มีนโยบายเรื่องแก้โค้ดโปรดักชัน → โมเดลเจอบั๊กจริงใน `reset()` และแก้พร้อมรายงานตรง ๆ แต่คำสั่งไม่ได้กำหนดไว้ ตอนนี้กำหนดชัดเจน
4. ช่องโหว่ที่ไม่ใช่เรื่องพรอมต์ (พบตอนทดสอบกับ Claude Code จริงก่อน E2E): โมเดลเขียน `.env` ผ่าน `printf > .env` ได้ ตอนนี้ guard บล็อกการเขียนไฟล์ที่ป้องกันผ่าน shell

## ข้อจำกัด (อ่านก่อนเชื่อตัวเลข)

- **โปรเจกต์เดียว หนึ่งรอบต่อโมเดล** ผลของโมเดลไม่คงที่ รอบอื่นอาจต่างได้ นี่คือหลักฐานว่า "ใช้ได้จริงอย่างน้อยหนึ่งเส้นทาง" ไม่ใช่สถิติ
- เป็นเว็บแอปเล็กที่ไม่ต้องติดตั้งแพ็กเกจ ไม่ครอบคลุมโปรเจกต์ใหญ่ ฐานข้อมูล หรือ monorepo
- เช็กเป็น **ตัวแทนเชิงโครงสร้าง** (ไฟล์มี เทสต์ผ่าน commit มี) ไม่ได้วัดว่าโค้ด UI "สวย" หรือสเปก "ฉลาด" และ `/vibe-ui` ไม่ได้เปิดเบราว์เซอร์จริงในการทดสอบนี้
- ตัวเช็กสามข้อถูกแก้เพราะผมเขียนผิดเอง (SPEC นับเฉพาะเลขข้อ, ต้องพูดคำว่า beep ใน resume, ห้ามแตะโค้ดโปรดักชันโดยไม่ดูเหตุผล) ดูประวัติใน git
- ไม่ได้ครอบคลุม `/vibe-spec`, `/vibe-clean`, `/vibe-update` และไม่ได้ทดสอบ Fable
- ทดสอบบน Windows เท่านั้น
