# คู่มือ: vibe coding ด้วย Tool_VibeCode

## แนวคิด 5 ข้อ

1. **ผลลัพธ์ก่อนวิธีการ** — บอกว่าผู้ใช้จะเห็น/ทำอะไรได้ ไม่ต้องสั่งว่าใช้ฟังก์ชันไหน
2. **เส้นชัยต้องตรวจได้** — "กดปุ่มแล้วได้ไฟล์ CSV" ตรวจได้, "ใช้ง่าย" ตรวจไม่ได้
3. **ชิ้นเล็กที่รันได้** — ทุกรอบต้องได้ของที่เปิดดู/รัน/เทสต์ได้ ไม่ใช่ "เขียนไปก่อนค่อยมารวม"
4. **ให้ AI พิสูจน์** — ไม่เชื่อ "น่าจะได้แล้ว" ต้องเห็นผลรันจริง
5. **สถานะอยู่ในไฟล์ ไม่ใช่ในความจำ** — `docs/TASKS.md` และ `docs/HANDOFF.md` คือความจำของโปรเจกต์

## เส้นทางที่ 1: โปรเจกต์ใหม่

```text
vibe new C:\work\my-app --git      (ในเทอร์มินัลปกติ) หรือให้ Claude ทำผ่าน /vibe-start
cd C:\work\my-app && claude

/vibe-start อยากทำเว็บจองคิวร้านตัดผม ลูกค้าจองผ่านมือถือ
```
Claude จะถามไม่เกิน 3 ข้อ เลือก stack ที่ง่ายที่สุดจากเครื่องมือที่มีจริง สร้าง `docs/SPEC.md` กับ `docs/TASKS.md` และทำชิ้นแรกให้รันได้

ตรวจ **"สมมติฐาน"** ใน SPEC ก่อนเสมอ — การแก้ที่ต้นทางถูกกว่าการแก้ทีหลังหลายเท่า จากนั้น:

```text
/vibe-plan          แตกเป็นงานชิ้นเล็ก เรียงจากเสี่ยงสุดก่อน
/vibe-build         ทำงานชิ้นถัดไป (หรือ /vibe-build 3 ระบุงาน)
```

## เส้นทางที่ 2: โปรเจกต์ที่มีอยู่แล้ว

```text
/vibe-explain project      ให้อธิบายโครงสร้างเป็นภาษาคนก่อน (ไม่แก้ไฟล์)
/vibe-spec เพิ่มระบบ ...   เขียนสเปกฟีเจอร์ใหม่ให้เข้ากับของเดิม
/vibe-plan → /vibe-build
```
ถ้ายังไม่มี `AGENTS.md` ให้ `vibe new . ` (ไม่ทับไฟล์ที่มีอยู่ เพิ่มเฉพาะที่ขาด) แล้วเติมส่วน Commands ให้ตรงของจริง — นี่คือส่วนที่ทำให้ AI ตรวจงานตัวเองได้

## ระหว่างทำงาน

| สถานการณ์ | ทำอะไร |
|---|---|
| มี error / บั๊ก | `/vibe-fix <แปะ error เต็ม ๆ>` — จะทำซ้ำให้เกิดก่อน หาสาเหตุราก แก้ แล้วเพิ่มเทสต์ |
| หน้าตาไม่ดี | `/vibe-ui <หน้า>` — ตรวจ hierarchy, ระยะ, responsive, ทุกสถานะ, การเข้าถึง |
| ไม่แน่ใจว่าโค้ดทำอะไร | `/vibe-explain <ไฟล์หรือ error>` |
| คำขอยังกำกวม | `/vibe-brief <ขอแบบคร่าว ๆ>` — แปลงเป็น brief ที่ชัด ก่อนสั่งงานจริง |
| AI วนแก้ซ้ำ | ใช้พรอมต์ [06-stuck-loop](../kit/prompts/06-stuck-loop.md) |
| แก้เสร็จชิ้นหนึ่ง | `/vibe-review` ให้ subagent อีกตัวตรวจ diff (ตาที่ 2 ไม่ใช่คนเขียน) |
| ก่อน merge / ปล่อย | `/vibe-sec` แล้ว `/vibe-ship` (ไม่ push ให้เองจนกว่าจะอนุญาต) |
| คุยยาว / AI เริ่มสับสน | `/vibe-handoff` → ปิด → เปิด `claude` ใหม่ (hook โหลดสถานะให้) → `/vibe-resume` |

## เคล็ดที่ได้ผลจริง

- **เก็บ `AGENTS.md` ให้สั้น** (ไม่เกินราว 100 บรรทัด) เติมกฎเมื่อ AI พลาดซ้ำเท่านั้น กฎที่ยาวและกว้างถูกมองข้าม
- **commit บ่อย** หลังทุกชิ้นที่เขียว ถ้าพัง `git diff` / `git checkout` ย้อนได้ทันที (permission ให้ `git commit` ผ่านโดยไม่ถามแล้ว แต่ `git push` ยังถามเสมอ)
- **อย่าอ่านทุกบรรทัด แต่ให้ตรวจสิ่งเหล่านี้**: สมมติฐาน, ผลรันเทสต์, ไฟล์ที่ถูกแก้ (ตรงขอบเขตไหม), dependency ใหม่, การลบข้อมูล
- **ใช้ subagent กับงานอ่านเยอะ** (สำรวจโค้ด, รีวิว, ตรวจความปลอดภัย) เพื่อไม่ให้ context หลักเต็ม
- **ใช้ MCP แค่ที่จำเป็น** — `vibe mcp context7 --apply` (docs ล่าสุด) และ `playwright` (ให้ AI เปิดเว็บดูเอง) พอสำหรับเริ่ม; ทุก MCP เพิ่ม context และพื้นผิวความเสี่ยง
- **Secret**: ใส่ใน `.env` (ถูก ignore) เอง อย่าแปะลงแชท guard จะกันไม่ให้ AI เขียนลงไฟล์โค้ด แต่ไม่รู้ว่าคุณพิมพ์ในแชทหรือเปล่า

## ดูแลชุดเครื่องมือให้ทันสมัย

| ต้องการ | ทำอะไร |
|---|---|
| รู้ว่ามีอะไรใหม่ | เปิด session ใหม่แล้ว Claude จะแจ้งถ้ามีเวอร์ชันใหม่ (เช็กวันละครั้ง) หรือ `/vibe-update --check` |
| อัปเดต | `/vibe-update` ใน Claude Code หรือ `node bin/vibe.mjs update` ในเทอร์มินัล — แสดง changelog ของสิ่งที่เปลี่ยน แล้วเปิด Claude Code ใหม่ |
| ตรวจสุขภาพ | `node bin/vibe.mjs doctor --updates` |
| ผิดพลาด/อยากย้อน | `node bin/vibe.mjs backups` แล้ว `node bin/vibe.mjs restore <ชื่อ>` |
| ย้ายโฟลเดอร์ Tool_VibeCode ไปที่อื่น | รัน `node bin/vibe.mjs install` จากที่ใหม่หนึ่งครั้ง (อัปเดต launcher ให้) |

อัปเดตไม่ทับไฟล์ที่คุณแก้เอง (จะบอกว่าข้ามไฟล์ไหน) — อยากให้การปรับแต่งของคุณอยู่ถาวรและย้ายเครื่องได้ ให้แก้ใน `kit/` ของ clone ของคุณ (fork) แล้ว commit ดู [CUSTOMIZE.md](CUSTOMIZE.md)

## Definition of Done (ย่อ)

รัน test/lint/build แล้วเห็นผลเอง · ลองใช้ฟีเจอร์จริง · มีเทสต์สำหรับตรรกะใหม่/บั๊กที่แก้ · ไม่มี debug/TODO/placeholder ค้าง · ไม่มี secret · diff ทุกบรรทัดจำเป็น · `docs/TASKS.md` ตรงความจริง
รายการเต็ม (เว็บ, API, ข้อมูล, สคริปต์) อยู่ใน `kit/claude/skills/vibe-workflow/references/definition-of-done.md`
