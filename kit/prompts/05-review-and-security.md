# ตรวจงานก่อน merge / ปล่อย

## รีวิวโค้ด
```
รีวิวการเปลี่ยนแปลงล่าสุด ([diff ที่ยังไม่ commit / branch ... / PR #...]) แบบคนที่ไม่ได้เขียนเอง
ตรวจตามลำดับ: ความถูกต้อง (logic, edge case, async) → ความปลอดภัย → ความเสี่ยงต่อข้อมูล → เทสต์ (ขาด/ถูกลดมาตรฐานไหม) → การแก้นอกขอบเขต/โค้ด debug ตกค้าง
อ่านโค้ดรอบ ๆ ให้เข้าใจก่อนฟันธงว่าผิด อันที่ยืนยันไม่ได้ให้ระบุว่า "ไม่แน่ใจ"
รายงานเรียงตามความรุนแรง: ไฟล์:บรรทัด, อะไรผิด, สถานการณ์ที่ทำให้พัง, วิธีแก้ ถ้าไม่เจออะไรเลย ให้บอกว่าตรวจอะไรไปบ้าง
ห้ามแก้ไฟล์ จนกว่าฉันจะสั่ง
```

## ตรวจความปลอดภัย
```
ตรวจความปลอดภัยของ [ทั้งโปรเจกต์ / ส่วน ...]:
- secret หลุดในโค้ด/ประวัติ git/ไฟล์ตัวอย่าง (อย่าพิมพ์ค่าจริง บอกแค่ไฟล์ บรรทัด ประเภท และให้ฉัน rotate)
- login/สิทธิ์ ถูกเช็กที่ฝั่งเซิร์ฟเวอร์ทุกจุด ผู้ใช้เห็นข้อมูลของคนอื่นได้ไหม
- อินพุต: SQL/command injection, XSS, path traversal, อัปโหลดไฟล์, SSRF
- เว็บ: CSRF, CORS, cookie flags, redirect
- dependency มีช่องโหว่ไหม (รัน audit ถ้ามี)
- log/error เปิดเผยข้อมูลสำคัญไหม
จัดระดับความรุนแรง + วิธีโจมตีที่เป็นไปได้ + วิธีแก้ที่เจาะจง
```
