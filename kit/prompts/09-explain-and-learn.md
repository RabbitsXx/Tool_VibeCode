# ไม่เข้าใจโค้ด — อยากเรียนรู้ไปด้วย

## อธิบายโปรเจกต์ทั้งก้อน
```
อ่านโปรเจกต์นี้จริง ๆ แล้วอธิบายให้คนที่ไม่ใช่โปรแกรมเมอร์เข้าใจ:
1. มันทำอะไร (1 ประโยค ในมุมสิ่งที่ผู้ใช้เห็น)
2. แผนที่โฟลเดอร์: อะไรอยู่ตรงไหน
3. ข้อมูลไหลจากไหนไปไหน เล่าเป็นเรื่อง เริ่ม→กลาง→จบ
4. ไฟล์ 3 ไฟล์ที่ควรอ่านก่อน
5. ส่วนไหนเปราะบาง แก้แล้วเสี่ยงพัง ส่วนไหนแก้ได้สบาย
ห้ามแก้ไฟล์
```

## อธิบาย error
```
error นี้แปลว่าอะไรในภาษาคน, น่าจะเกิดจากอะไรในโปรเจกต์ของฉัน (ดูโค้ดจริง), และสิ่งแรกที่ควรลองคืออะไร:
[แปะ error]
```

## สอนระหว่างทำ
```
ทำงานนี้เหมือนเดิม แต่หลังจบให้เขียน "สิ่งที่ควรรู้" 3 ข้อ: แนวคิดสำคัญที่ใช้, ทำไมเลือกวิธีนี้แทนอีกวิธี, และถ้าอยากแก้เองทีหลัง ต้องดูที่ไฟล์ไหน
```
